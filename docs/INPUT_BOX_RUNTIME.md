# Native InputBox runtime

VBA `InputBox(...)` and `InputBox$(...)` return an actual native Qt dialog result.
Both the imported-layout host and the native table-form host use the same dialog.
The parser accepts a required prompt and positional title/default/xpos/ypos,
including omitted positional arguments. Explicit Null arguments fail with 94,
invalid argument counts with 450, position type mismatches with 13 and Long
position overflow with 6. A host without a dialog context fails with 3251.
Windows Help file/context arguments fail with 3251 before opening a dialog.

The dialog displays a plain-text, multiline prompt, selected default text,
OK/Abbrechen buttons and application modality. Enter/OK returns text;
Escape/Cancel returns a text value containing an empty string. No synthetic answer
is generated by the app. The editor accepts 255 UTF-16 code units; returned text
is limited to 254. Keyboard/context-menu paste, input-method commits and external
text drops retain only the first line. Position arguments are converted from
TWIPs using the owner's screen logical DPI; omitted positions center horizontally
and place the dialog approximately one third down the available screen.

Regression tests exercise the actual modal event loop, real key/button input,
default text selection, literal HTML-looking prompts, cancellation without
closing the form, 255/254 limits, clipboard line truncation and Unicode IME commit.
The results are saved through the native bound form and checked in real SQLite
rows, including a non-NULL empty text value after Cancel. Core-only tests cover
typed argument errors, optional slots, numeric conversion and explicit host absence.

Original-source inventory finds two InputBox calls in one original procedure in
module SHA-256
`6e8e0a0e41e1a1768cff4a0b79a07205c7b0f799eb8b465af5397843ce048ed8`.
Both calls use positional arguments. This source inventory is not execution of
that original procedure or proof of the original authentication workflow. The
procedure also depends on form state and DAO; no original password or credential
was printed, copied into a test, or used as a dialog test value.

Boundaries remain: named argument syntax, statement-style invocation, Windows
Help integration, exact Access 2003 dialog rendering, complete multi-monitor/
physical-DPI positioning and primary-selection clipboard behavior are not verified.
The dialog title defaults to the host application name LinAccess. General VBA
string coercion/Unicode semantics retain their separately documented limits.
